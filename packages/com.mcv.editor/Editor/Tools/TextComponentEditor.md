# Contract: TextComponentEditor

Role: custom inspector for TextComponent — pushes the editor literal down to the control, and registers / unregisters a language clip in LanguageDataSO through `TextKeyTools`, re-exporting the JSON every time.

Methods:
OnInspectorGUI()  detect edits, push the literal to the control, then show the registration state with the register / delete button
PushLiteralToControl(comp)  private static; the one-way editor push `text` -> the node's TMP and/or Legacy control (the control text is its downstream display)
FindLanguageSO()  find the project LanguageDataSO (first one when several exist; the registration path itself blocks on duplicates)
RegisterWithExistingKey(so, comp, key)  private; when a key is already set but its clip is missing, add the clip under that key
DeleteClip(so, key)  private; remove the matching clip, clear the component's key and re-export
SetKey(value)  private; write `languageKey` through SerializedProperty so undo and the dirty flag stay correct
CreateClipsWithLiteral(comp)  private static; one empty slot per LanguageType with the Chinese slot filled from the **serialized `text`** field

Notes:
- Marked CustomEditor(typeof(TextComponent)).
- **The Chinese slot is read from the serialized `text` field (`LiteralText`), never from the runtime `RawText`.** `RawText` is only assigned by `ApplyRawText` at runtime, so in the editor it is always empty — that bug is exactly why newly registered clips used to end up with a blank Chinese slot (B2).
- New keys are generated by `TextKeyTools` as the path-style `{prefab asset path}/{node path}` (§3); this inspector no longer invents `ui.{GameObject name}` keys, and a duplicate key is refused rather than overwritten.
- The runtime resolves the latest text by clip id from JSON, so every write also re-exports the SO (single target `Export()`, never `ExportAll()`).
- The one-way push is deliberate: `text` is the input surface, the control is the display. Editing the control directly in the scene is not the entry point.
