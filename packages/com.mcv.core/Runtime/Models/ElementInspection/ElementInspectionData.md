# Contract: InspectionData (+ CheckPointData)

Role: inspection data of one tested component; records the expected reading of every terminal pair, split into a correct group and a wrong group.

Fields:
rightCheckPointDatas:List<CheckPointData>  terminal pairs that are correct on this inspection page
wrongCheckPointDatas:List<CheckPointData>  terminal pairs that are deliberately wrong (reading still shown, flagged wrong)
checkPoints:InspectionElementPointObj[]  the two points of the pair, order-independent
resistance:float  resistance in Ohm (0 = conducting; use openCircuit for an open circuit)
current:float  current in A
voltage:float  voltage in V
openCircuit:bool  open circuit (infinite resistance): resistance gears show OL and the resistance number is ignored
hasActuated:bool  whether the actuated state has its own readings
actuatedResistance / actuatedCurrent / actuatedVoltage:float  readings used once the component is actuated
actuatedOpenCircuit:bool  open circuit in the actuated state

Methods:
(none)

Notes:
- Two groups exist because the same terminal pair is not equally correct on every inspection page: on a contactor the correct pair of 检测1 触点 is the NC pair while 检测2 线圈 uses A1-A2.
- InspectionMultimeterObj judges: correct group -> IsPairCorrect = true, wrong group -> the reading is shown but flagged wrong, neither group -> Err on screen.
- openCircuit is an explicit switch rather than float.PositiveInfinity: open circuits are very common in the teaching data (NO contacts not pulled in, broken coil, blown fuse) and infinity can neither be typed in the inspector nor serialised and displayed reliably.
- Pairs are generated by the inspector inspection panel (rules in ElementCheckPointPairing); the designer only fills in the readings.
- A pair with hasActuated unset keeps the same reading before and after actuation, which is correct for coils and windings.
- The contract document is named after the file (ElementInspectionData.md) while the main type is InspectionData.
